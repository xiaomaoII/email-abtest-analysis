# 业务说明与分析约定

## 决策与用户

假设你服务于一家零售企业的用户运营负责人。对方关心：向近期曾购买的客户发送不同主题邮件，相比不发送，是否增加两周收入？这种增量是否值得触达投入？下一轮该优先验证什么？

本项目使用 Hillstrom 于 2008 年公布的历史数据，练习业务分析和实验决策。没有本人执行的业务投放，不能写成公司内部业绩。

## 实验与估计目标

- 合格人群：过去十二个月曾购买的客户，共约 64,000 人。
- 随机化单位：客户；原作者描述三组各分配约三分之一。
- 对照组：不发邮件；实验组：男装主题邮件、女装主题邮件。
- 观察窗：发出营销邮件之后两周。
- 目标量：实验组与对照组全部客户平均消费金额之差，代表该实验人群的平均收入增量。
- 原始数据没有真实客户 ID 和分流日志，无法独立核实串组或实施过程。作者的随机试验说明是设计依据。

## 指标与比较

| 类型 | 定义 | 在决策中的作用 |
| --- | --- | --- |
| 主指标 | SUM(spend) / COUNT(*)，美元/客户 | 判断收入增量及其不确定性 |
| 辅助指标 | SUM(conversion) / COUNT(*) | 解释购买发生率变化 |
| 辅助指标 | SUM(visit) / COUNT(*) | 解释访问发生率变化 |
| 收益情景 | 人均收入增量 × 假设毛利率 − 假设触达成本 | 提出盈亏平衡条件，不是实际利润 |
| 待补护栏 | 退订、投诉、长期留存、退款等 | 下一轮必须定义并采集，本数据无法判断 |

两种邮件各自与对照比较。收入构成两个主要假设的家族，默认双侧 alpha=0.05，Holm 校正。辅助结果只作解释。本轮不做邮件之间的确认性优胜判断。

这些约定在项目分析实现中固定，但不是原实验团队的事前注册。复盘不伪造历史预注册。

## 数据处理规则

保留原始文件、零收入和高收入记录。缺失值、非法范围、组别缺失或结果矛盾时停止，先核实。相同字段值不能视为重复用户。原数据中 `Surburban` 是类别拼写，分析层统一为 `Suburban` 并记录数量，原文件不改动。

分群提前固定为新老客户、历史消费 ≤100 / 100–350 / >350 美元、距上次购买 1–3 / 4–6 / 7–12 个月。不能根据结果反复修改切点。分群结论只产生下一轮假设。

## 决策原则

首先检查数据与分流，再判断收入证据。正向统计证据不足以直接推广：还需要可接受的实际成本、稳健的净收益边界、护栏和当前业务验证。证据不足时讨论区间与业务门槛；负向证据时建议暂停并排查。不以“必须显著”作为项目成功标准。
