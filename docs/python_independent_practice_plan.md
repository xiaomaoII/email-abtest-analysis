## 1. 目标与已有基础

目标是在已有业务和统计理解基础上，亲手完成“读数据 → 检查 → 汇总 → 效果分析 → 分群 → 成本与结论”的Python流程，能够排错、修改条件和解释结果；同时掌握Git版本管理、GitHub同步和协作，发布可复现的求职作品。

“独立实现”允许查官方文档、使用pandas、NumPy、SciPy、statsmodels等库，不要求从零重写统计库，也不要求背诵API。核心是用户能够组织输入、调用方法、处理输出、核验结果并解释分析选择。

本阶段不追求机械重抄整个项目，不扩展网页、复杂机器学习或真实投放。首版不增加CUPED、GitHub Actions或复杂分支策略。本人摘要随作品整理完善，完成Python与Git实操及发布验收后，再定稿简历和面试表达。

## 2. 协作与教学方式

每次只推进一个小任务，而不是一次交付一个大章节的答案：

1. Agent讲清业务问题、原理、数据口径及本次要得到的结果；逐个解释必要术语。
2. Agent讲任务必需的Python语法，可以用独立小例子演示；默认不预先给整段项目答案。
3. 用户先写代码并运行。遇到错误时先解释报错位置及原因，按需给提示；若用户明确要求完整参考实现，可以提供，但如实记录辅助程度。
4. Agent评审正确性、分母、数据筛选、方法参数和输出含义，帮助用户自己修改。不能只要求抄表里的数值。
5. 用户完成一个小变式，并用自己的话说明关键选择。依此判断是否能迁移，而不只看复制后的输出。

Python基础随任务学习：变量、导入、路径、DataFrame、筛选、分组、数组、循环、函数和简单断言。不把所有语法一次性讲完，也不因为一个新语法就重启整个统计课程。

Git教学同样采用“原理与目的 → 必要操作 → 用户执行 → 输出解释 → 评审”。Agent不代替用户完成首次提交、推送或PR来宣称用户已掌握；发生错误先检查当前状态，再推进下一小步。

## 4. 六项任务与验收标准

### P1：读取与检查数据

**为什么做：**先知道表里有什么、每行是什么、是否存在会改变分析口径的问题。

**必需语法：**导入库、变量、文件路径、DataFrame、行列信息、列选择、条件表达式。

**用户亲手完成：**

- 读取本地CSV，查看前5行、行列数、字段名及类型。
- 统计各列缺失、三个实验组人数、零消费人数。
- 理解`visit`、`conversion`的0/1及`spend`金额；检查值域和购买/消费一致性。
- 将异常检查与数据删除区分开；不自动填零、不去除零消费或按相同属性去重。

**产物与验收：**代码在新内核按顺序运行；读到64000行、三个组、63422名零消费客户；能解释每个检查目的。前5行仅是预览，正式数据变量不能被截断成5行。

**小变式：**独立统计另一项条件，例如未访问人数，并解释其含义。新条件由任务进行时确定。

### P2：用Python复现自己的SQL汇总

**为什么做：**把已经接触的SQL分组思想迁移到pandas，同时验证指标分母。

**必需语法：**`groupby`、聚合、列命名、排序、索引与结果表。

**用户亲手完成：**按邮件策略计算客户数、访问人数、购买人数、总收入、人均收入、访问率和购买率；用总收入/客户数与平均值两种方式理解人均收入；与已有练习SQL结果核对。

**产物与验收：**输出三组指标，结果与SQL一致；能解释`size/count`遇到缺失时的区别、0/1均值为何是比例。保留所有客户，不先筛`conversion=1`或`visit=1`。

**小变式：**增加一项分组指标或改变输出顺序，并能指出主指标分母保持不变。

### P3：总体效果、Welch与Holm

**为什么做：**从组均值走到邮件增量及其不确定性，明确检验的比较对象。

**必需语法：**布尔筛选、Series/数组、均值与样本方差、函数返回值、结果整理。

**用户亲手完成：**

- 提取一种邮件组及不发邮件组，计算人数、均值、收入差、样本方差及均值差标准误。
- 调用SciPy的Welch检验，识别双侧假设、`equal_var=False`、p值及置信区间；与自己的均值差和SE核对。
- 扩展到第二种邮件，整理结果并对两项收入p值调用Holm校正。
- 区分原始p、校正p、单项区间、相对提升；对照均值为0时不能照常除法计算相对提升。

**产物与验收：**两种邮件各自对照结果与参考表一致，能解释每个输入/输出；不能以两项显著性或点估计大小宣布邮件之间优胜。允许调用统计库，不以调用已有项目总函数代替本任务。

**小变式：**切换处理组或交换比较方向，预判效应符号与双侧p值如何变化，再核验。

### P4：亲手实现Bootstrap过程

**为什么做：**把“组内有放回重抽”变成明确的数据和循环操作，而不是只调用已写好的函数。

**必需语法：**随机数生成器、抽样、循环、数组/列表、分位数、参数。

**用户亲手完成：**先在小数组上完成一次两组独立重抽与均值差，再重复并保存每次差异，计算百分位区间；随后迁移到真实收入数组。先少量重复调试，正式与项目对照时使用5000次和明确种子。

**产物与验收：**各组重抽人数与原组一致、包含零值；能解释有放回、固定种子和区间。不同随机数调用顺序/分批方式可能造成区间端点的小幅差异，不能仅以是否逐位复现参考函数判断正确；若声称精确复现，需保持相同随机数调用方式。

**小变式：**改变种子或重复次数，说明点估计、模拟区间及Monte Carlo波动的区别。Bootstrap和Welch接近支持稳健性，不互相证明正确。

### P5：分群与交互检验

**为什么做：**区分“某人群邮件有效”与“不同人群的邮件效果不同”，亲手连接分组表和回归检验。

**必需语法：**映射、分箱、多列分组、透视/展开、分类变量、模型拟合及限制表达式。

**用户亲手完成：**

- 使用实验前`newbie/history/recency`生成分群，确认分箱边界。
- 从新老客户开始计算六组均值、各自邮件增量及新减已有的增量差。
- 调用statsmodels构建组别×客户类型模型，理解参照类别，指定HC3，明确联合H0后调用Wald；扩展到其他两个维度，并对三个维度做探索性Holm。
- 展示各单元人数和购买人数，理解稀疏结果、共享对照以及不同检验对象。

**产物与验收：**能将交互项与手算增量差对应，解释哪些系数在联合受检验；原始p和探索性校正p对应的家族清楚。不用实验后结果分群，不把不显著解释为相等或证实差异。

**小变式：**更换参照类别，说明系数表达会变，而同一完整联合假设的判断应保持一致。无需从零实现statsmodels，但要能自行设定正确模型和检验。

### P6：成本情景与流程整合

**为什么做：**让同一套数据处理和推断支持不同成本假设，最终形成可解释的业务结果。

**必需语法：**自己定义函数、参数与返回值、循环/列表、DataFrame、简单条件判断及断言。

**用户亲手完成：**

- 写净收益函数，计算收入增量×固定假设毛利率−增量触达成本。
- 正确取得项目口径的Bonferroni收入区间（两项比较各97.5%），对其端点作相同变换，计算盈亏平衡点和下界阈值。
- 遍历多种毛利率/成本，区分区间全正、全负、跨零或触零；参数非法时明确处理，不悄悄生成误导结果。
- 将P1—P6按顺序组织，重新启动内核后从头执行；不依赖旧Notebook留在内存中的变量。用SQL、SciPy及参考表作必要核验，解释合理的浮点误差。

**产物与验收：**修改一个参数后可重算；输出能追溯到原始数据，毛利率和成本均标为假设，收益区间只包含收入估计的不确定性。能说明历史效果不能自动外推到当前业务。

**小变式：**采用一个未写在原配置中的成本，先预判点估计/区间符号再用自己代码检查；说明收益为正仍不等于已实现公司利润。
